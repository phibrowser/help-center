# プライベートAI

PhiのAI機能は、デフォルトでは**Phi Cloud**で動作します。**プライベートAI**を使うと、AIの作業の種類ごと、つまりタスクごとに、どこがその作業を担当するかを決められます。選べるのは、Phi Cloud、このMacにダウンロードしたモデル、またはOllama、LM Studio、OpenAI、OpenRouterなど自分で接続するAIプロバイダーです。

プライベートAIはデフォルトでオフです。一度もオンにしなければ、すべてのAI機能はこれまでどおり動作し、Phi Cloudを使います。

## アシスタント、Phi Cloud、AIプロバイダー {#assistant-phi-cloud-and-providers}

この3つは混同しやすいので、最初に区別しておきましょう。

- **アシスタント**は、あなたが名前を付けた相手です。Phiのエージェントであり、あなたが何を求めているかを読み取って、何をするかを決めます。ページを読む、ブラウザスキルを実行する、ブラウザで操作する、タスクを作成する、といった判断です。どのモデルを使っても同じアシスタントで、会話、メモリ、タスクはモデルによって変わりません。
- **モデル**は、アシスタントが考えるために借りる「頭脳」です。アシスタントは各ステップで必要なものをモデルに送り、モデルがそれに答えます。
- **AIソース**は、そのモデルがどこで動くかを決めるものです。次の3種類があります。
  - **Phi Cloud**、Phiに組み込まれたAIサービスです。エージェントではなく、特定の1つのモデルでもありません。Phiが接続し、あなたに代わって管理するクラウドモデルの集まりです。Phiへのサインインをそのまま使い、APIキーは不要で、モデルを選ぶ必要もありません。
  - **ローカルモデル**、このMacにダウンロードされ、このMac上で動くモデルです。
  - **自分のプロバイダー**、自分のアドレス、アカウント、APIキーを使って自分で接続するAIサービスです。

つまりPhi Cloudは、OllamaやOpenAIと同じ位置にあります。「アシスタントのモデルはどこで動くのか」という問いへの答えの1つです。違いは、Phi Cloudは組み込まれていてすぐに使えるのに対し、ほかは自分で設定するものだという点です。

### ソースの比較 {#comparing-sources}

|                                 | Phi Cloud                                                       | ローカルモデル                                     | 自分のローカルプロバイダー（Ollama、LM Studio）         | 自分のクラウドプロバイダー（OpenAI、OpenRouter、Codexなど） |
| ------------------------------- | --------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------- |
| 必要なもの                      | Phiへのサインインだけ                                           | 1回のセットアップ（モデルをダウンロード）          | OllamaまたはLM Studioがインストールされ、動いていること | そのサービスのアカウントまたはAPIキー                       |
| コンテンツの送り先              | Phiを経由して、Phiが使うモデルプロバイダーへ                    | どこにも送られず、このMacにとどまる                | 設定したアドレス（通常はこのMacか自分のネットワーク）   | Macからそのサービスへ直接                                   |
| 誰のアカウントとして届くか      | Phiのアカウント。モデルプロバイダーにはあなたが誰かは伝わらない | 該当なし                                           | 該当なし                                                | あなたのアカウント（自分のアカウントまたはキーを通じて）    |
| 費用                            | Phiに含まれる（[利用上限](/ja/ai/#usage-limits)の範囲内）       | 無料（このMacのメモリと処理能力を使う）            | 無料（動いているコンピューターのリソースを使う）        | そのサービスの料金体系に従う                                |
| Phiの利用上限にカウントされるか | はい                                                            | いいえ                                             | いいえ                                                  | いいえ                                                      |
| オフラインで使えるか            | いいえ                                                          | はい                                               | はい（このMac上で動いている場合）                       | いいえ                                                      |
| 品質                            | 安定していて、すべてのタスクに適している                        | モデルのサイズ次第で、通常はクラウドモデルより劣る | 選んだモデル次第                                        | 選んだモデル次第                                            |

Phi Cloudがコンテンツをどう扱うかについては、[プライバシーとデータ](/ja/privacy/)をご覧ください。自分のクラウドプロバイダーを使う場合は、そのプロバイダーのプライバシーポリシーが適用されます。

## Phiが自分のプロバイダーを使うとき {#when-phi-uses-your-provider}

プロバイダーを追加しただけでは、何も変わりません。Phiがそのプロバイダーを使うのは、次の両方を満たす場合だけです。

1. **プライベートAI → AIタスク**で、そのプロバイダーのモデルをいずれかのタスクのソースとして選んでいる。
2. **プライベートAI**のスイッチがオンになっている。

変更していないタスクは、引き続きPhi Cloudを使います。プライベートAIをオフにすると、すべてのタスクがすぐにPhi Cloudに戻りますが、選択内容は保持されるため、もう一度オンにすればセットアップし直さなくても元に戻ります。

## タスクごとにソースを選ぶ {#choosing-a-source-for-each-task}

プライベートAIは全か無かの機能ではありません。タスクごとに設定し、ページ上部には、Phi Cloud以外で動いているタスクの数が、たとえば**プライベートで実行中のAIタスク：4件中2件**のように表示されます。

| AIタスク       | 対象                                                         | 選べるソース                                                 |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **チャット**   | サイドバーとPhi Chatでの返答                                 | Phi Cloud、ローカルモデル、自分のプロバイダー、Codex         |
| **メモリ**     | ブラウジングからのメモリ作成や要約などのバックグラウンド作業 | Phi Cloud、ローカルモデル、自分のプロバイダー、Codex         |
| **Webタスク**  | ブラウザでのアシスタントの操作と、自動化                     | Phi Cloud、ローカルモデル、自分のプロバイダー、Codex         |
| **データ検索** | 接続したデータの検索                                         | Phi Cloud、またはPhiがダウンロードするローカル検索モデルのみ |

これらと並んで、ほかにもいくつかの行があります。

- <strong>ビジョンフォールバック。</strong>タスクに選んだモデルが画像を読めない場合、画像は代わりにここで設定したモデルに送られます。最初は**未設定**になっています。
- **AIによるタブ整理**は、macOSのApple Intelligenceが処理し、変更できません。Apple IntelligenceのないMacには表示されません。
- **画像生成**は常にPhi Cloudを使います。

タスクを別のソースに切り替えると、Phiはまずそのモデルをテストします。テストに失敗した場合、タスクは以前のソースに戻り、その理由が表示されます。

チャットがPhi Cloud以外のソースを使うようになると、チャットには**プライベートAIを使用しています**と表示されます。回答の品質がオンラインのモデルとは異なる場合があるためです。

## プライベートAIをオンにする {#turning-on-private-ai}

プライベートAIの設定を開く方法は2つあります。

- [Phi Chat](/ja/phi-chat/)で、上部バーの設定（歯車）ボタンをクリックし、**プライベートAI**を選びます。
- ブラウザで**設定 → PhiとAI → Phi Sentinel → プライベートAI**を開きます。Phi Chatの同じページが開きます。

初めてスイッチをオンにすると、PhiはこのMacでローカルモデルを実行できるかを確認します。

- **実行できる場合**、セットアップウインドウに、ダウンロードサイズ、実行中にモデルが使うおおよそのメモリ量、このMacに移るタスクが表示されます。**セットアップを開始**をクリックすると、Phiはローカルランタイムをインストールし、モデルをダウンロードして起動し、検証します。ウインドウを**最小化**して、セットアップをバックグラウンドで続けることもできます。完了するまでは、すべてのAI機能がPhi Cloudを使い続けます。
- **実行できない場合**、ウインドウにその理由が表示されます。それでも**自分のAIサービスを使用**をクリックすれば、ローカルモデルなしで自分のプロバイダーを接続できます。

### 必要な環境 {#requirements}

| 項目             | 要件                                                                  |
| ---------------- | --------------------------------------------------------------------- |
| チップ           | Appleシリコン。IntelプロセッサのMacではローカルモデルを実行できません |
| メモリ           | 16GB以上                                                              |
| 空きディスク容量 | 10GB以上、かつダウンロードサイズより2GB以上多いこと                   |

ネットワーク上の別のコンピューターで動くOllamaやOpenAIなど、自分のプロバイダーを接続するだけなら、これらの要件は関係ありません。

### セットアップでインストールされるもの {#what-setup-installs}

現在、セットアップでは2つのモデルがダウンロードされます。実行中は、2つ合わせて約7GBのメモリを使います。

- **Gemma 4 E4B (4-bit)**、**メモリ**用。
- **BGE-M3**、**データ検索**用。

**チャット**と**Webタスク**はPhi Cloudに残ります。この2つには、長いコンテキストとツール呼び出しを確実に扱えるモデルが必要です。Phiがこれらを自動的にこのMacへ移すのは、200億パラメータ以上のローカルモデルが利用できる場合だけです。セットアップでダウンロードされるGemmaモデルは約40億パラメータで、バックグラウンド作業には十分ですが、会話を担うには向きません。それでも、テストに合格すれば、**AIタスク**で手動でチャットをこのモデルに切り替えることはできます。セットアップが完了すると、どのタスクがこのMacで動くようになったかが正確に表示されます。

セットアップ後も、メモリが関連する項目を見つけるために使うインデックスは、引き続きPhi Cloudで作成されます。これもこのMacで行いたい場合は、**データ検索**のローカルモデルを一度手動で選んでください。両方がこのMacに移ります。

## OllamaまたはLM Studioを接続する {#connecting-ollama-or-lm-studio}

OllamaとLM Studioは、オープンモデルを自分のコンピューターで動かすための無料アプリです。どちらもプロバイダーとしてPhiに組み込まれていて、デフォルトのアドレスはOllamaが`http://127.0.0.1:11434`、LM Studioが`http://127.0.0.1:1234/v1`です。

1. OllamaまたはLM Studioをインストールして開き、モデルをダウンロードします（[おすすめのモデル](#recommended-models)を参照）。
   - Ollama：ターミナルで`ollama pull <model>`を実行します。たとえば`ollama pull gpt-oss:20b`です。
   - LM Studio：アプリでモデルを検索してダウンロードし、**Developer**ページでローカルサーバーを起動します。
2. Phi Chatで**設定 → AIプロバイダー**を開き、**Ollama**または**LM Studio**を選びます。
3. **このプロバイダーを使用**をオンにします。サービスがネットワーク上の別のコンピューターで動いている場合は、**ベースURL**をそのコンピューターのアドレスに変更します。
4. **読み込み**をクリックしてモデルを取得します。**モデルへのアクセス**で、**すべてのモデルを許可**を選ぶか、**選択したモデルのみ**を選んで使いたいモデルにチェックを入れます。
5. モデルを選んで**テスト**をクリックし、接続に成功したと表示されたら、**変更を保存**をクリックします。
6. **プライベートAI**に戻り、**AIタスク**で、移したいタスク（**チャット**など）にそのモデルを選びます。
7. **プライベートAI**のスイッチをオンにします。

OpenAI互換のAPIを持つほかのサービスには、**カスタムプロバイダーを追加**を使い、名前、ベースURL、そしてサービスが必要とする場合はAPIキーを入力します。

知っておきたい点がいくつかあります。

- ベースURLには`http`と`https`のどちらも使え、APIキーは省略できます。ローカルのサービスでは通常キーは不要だからです。`http`のアドレスに送られたキーは暗号化されずに送信されるため、自分のMacやネットワーク上にないものには`https`を使ってください。
- OllamaやLM Studioは開いたままにしておく必要があります。コンピューターがスリープしたりアプリが終了したりすると、影響を受けるタスクは[フォールバックの設定](#when-a-local-source-is-unavailable)に従います。
- Webタスクや長い会話では、大量のテキストがやり取りされます。返答が途中で切れたり、アシスタントが操作を最後までできなかったりする場合は、コンテキスト長を32Kなどに引き上げてください。Ollamaでは設定の**Context length**で、LM Studioではモデルを読み込むときの**Context Length**で変更します。コンテキストを長くすると、メモリの使用量が増えます。
- ネットワーク上のほかのコンピューターからOllamaに接続するには、そのコンピューターのOllamaがネットワークアドレスで待ち受けている必要があります（`OLLAMA_HOST=0.0.0.0`）。

## おすすめのモデル {#recommended-models}

オープンモデルの進化は速いため、以下のモデル名は例として扱ってください。同じサイズのより新しいモデルでも同じように使えます。最も重要なのは2点、モデルが十分に大きいことと、メモリに収まることです。実行中のモデルは、おおよそダウンロードサイズに数GBを加えた量のメモリを使います。macOSやほかのアプリのための余裕も必要です。

| Macのメモリ | おすすめ                                                                                                                                                        |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 16GB        | セットアップを使ってメモリとデータ検索をこのMacで動かし、チャットとWebタスクはPhi Cloudのままにします。このメモリ量では、チャットに適したモデルを載せられません |
| 32GB        | チャット用に200億パラメータ級のモデルを動かせます。たとえば**gpt-oss-20b**（Ollama：`gpt-oss:20b`）や**Qwen3 30B**（Ollama：`qwen3:30b`）です                   |
| 64GB        | より安定した300億パラメータ級のモデルを選べます。たとえば**Qwen3 32B**（Ollama：`qwen3:32b`）で、長いコンテキストにも余裕があります                             |
| 128GB以上   | 1000億パラメータ級のモデルを動かせます。たとえば**gpt-oss-120b**（Ollama：`gpt-oss:120b`）で、クラウドモデルにより近づきます                                    |

タスク別の目安は次のとおりです。

- **チャットとWebタスク**：200億パラメータ以上で、ツール呼び出し（関数呼び出し）に対応したモデルを選んでください。ツール呼び出しに最も大きく依存するのはWebタスクで、小さなモデルではよく失敗します。
- **ビジョンフォールバック**：画像を読めるモデルを選んでください。たとえばGemma 3 12B（Ollama：`gemma3:12b`）やQwen2.5-VL 7B（Ollama：`qwen2.5vl:7b`）です。
- **メモリ**：セットアップで入るGemmaモデルで十分で、通常は変更する理由はありません。
- **データ検索**：Phiがダウンロードするローカル検索モデルか、Phi Cloudのみです。

どれほど大きくても、ローカルモデルは通常、Phi Cloudを支える最先端のモデルには及びません。コンテンツをMac上にとどめることよりも回答の品質を重視するなら、チャットとWebタスクをPhi Cloudのままにしておくのは理にかなった選択です。

## ローカルのソースが利用できないとき {#when-a-local-source-is-unavailable}

ローカルモデル、Ollama、LM Studioが応答しなくなると、Phiは**ローカルまたはセルフホストのソースが利用できない場合**の設定に従います。

- **自動的にPhi Cloudに切り替える（デフォルト）**。影響を受けるタスクは一時的にPhi Cloudを使うため、AI機能は動き続けます。これは、その間、それらのタスクのコンテンツがクラウドに送られるということでもあります。
- **影響を受けるAI機能を一時停止（クラウドにデータを送信しない）**。影響を受ける機能は、ローカルのソースが再び応答するまで一時停止します。

プライベートAIをオンにした理由が、コンテンツをこのMacにとどめることなら、2つ目のオプションを選んでください。

この設定が対象とするのは、ローカルおよびセルフホストのソースだけです。OpenAI、OpenRouter、Codexなどのクラウドプロバイダーで問題が起きても、PhiはPhi Cloudに切り替えません。

問題が起きると、プライベートAIのページに**要対応**と表示され、**ローカルサービスを再起動**ボタンが表示されます。

## Codexを使う {#using-codex}

ChatGPTのサブスクリプションがあり、このMacでCodexにサインインしている場合は、そのサブスクリプションをAIプロバイダーとして使えます。**設定 → AIプロバイダー → Codex**を開き、**接続**をクリックします。PhiはCodexがすでに保持しているサインイン情報を使い、資格情報をコピーすることはありません。

- 先にCodexをインストールし、ターミナルで`codex login`を実行してください。キーチェーンに保存されたCodexのサインイン情報は、Phiからは読み取れません。
- Codexは、チャット、メモリ、Webタスク、ビジョンフォールバックに使えますが、データ検索には使えません。
- Codexが行う処理は、ChatGPTのサブスクリプションの利用上限にカウントされます。上限に達したり、サインインが無効になったりしても、Phiはほかのソースに切り替えません。

## オフにする、リセットする {#turning-off-and-resetting}

- **プライベートAIをオフにする**には、そのスイッチを使います。すべてのタスクがすぐにPhi Cloudに戻り、ダウンロード済みのモデルと選択内容は保持されます。
- **プロバイダーを削除する**には、そのプロバイダーのページで**プロバイダーを削除**を使います。そのプロバイダーを使っていたタスクはPhi Cloudに戻ります。
- **リセットする**には、**詳細設定**の**AI設定をリセット**を使います。すべてのタスクがPhi Cloudに戻り、プロバイダーとそのAPIキーが消去され、ローカルモデルが削除されます。

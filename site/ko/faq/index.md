# 자주 묻는 질문

Phi Browser에 관해 자주 묻는 질문의 빠른 답변을 주제별로 모았어요. 전체적인 그림과 Phi가 이렇게 만들어진 이유가 궁금하다면 [가이드](/ko/what-is-phi-browser/)를 읽어 보세요. Phi Browser가 처음이라면 [시작하기](/ko/get-started/)를 참고하세요.

## 레이아웃과 탐색

::: details 세 가지 레이아웃 모드는 무엇인가요?
Phi에는 화면 공간과 익숙함을 서로 맞바꾸는 세 가지 모드가 있어요. **성능** 모드는 페이지에 가장 많은 공간을 주고, 탭과 북마크를 세로 사이드바에 담아요. **균형** 모드는 사이드바를 유지하면서 콘텐츠 위에 주소 표시줄을 더해요. **여유** 모드는 전통적인 브라우저와 가장 비슷해서, 탭이 위쪽에 있고 주소 표시줄이 항상 보여요. 온보딩에서 하나를 선택하고, 언제든지 바꿀 수 있어요.
:::

::: details 어떤 레이아웃으로 시작하는 게 좋을까요?
Chrome이나 Safari에서 넘어왔다면 가장 자연스럽게 적응할 수 있는 **여유** 모드로 시작해 보세요. 주소 표시줄이 보이는 현대적인 사이드바 브라우저를 원한다면 **균형**을 써 보세요. 페이지 공간을 최대한 넓히고 싶다면 **성능**을 사용하세요. 더 자세한 이전 가이드는 [Phi로 전환하기](/ko/switching-to-phi/)를 참고하세요.
:::

::: details 왜 세로 사이드바인가요?
요즘 화면은 대부분 세로보다 가로가 길어요. 읽고, 쓰고, 조사할 때 먼저 부족해지는 것은 세로 공간이에요. 그래서 세로 사이드바가 요즘 디스플레이의 비율을 더 잘 활용하고, 실제 페이지에 더 많은 공간을 남겨 줘요.
:::

## 스페이스와 프로필 {#spaces-profiles}

::: details 스페이스와 프로필은 무엇이 다른가요?
**스페이스**는 사이드바 안의 작업 공간으로, 자기만의 이름, 아이콘, 색상, 북마크를 가져요. **프로필**은 그 아래에 있는 격리 계층이에요. 프로필마다 쿠키, 방문 기록, 로그인 정보, 확장 프로그램이 따로 있어요. 스페이스는 보이는 모습과 사용감을 정리하고, 프로필은 무엇을 서로 분리해 둘지 결정해요. 전체 그림은 가이드의 [스페이스와 프로필](/ko/spaces/)을 참고하세요.
:::

::: details 프로필 하나가 여러 스페이스를 가질 수 있나요?
네. 각 스페이스는 정확히 하나의 프로필에 속하지만, 하나의 프로필이 여러 스페이스를 뒷받침할 수 있어요. 같은 프로필을 쓰는 스페이스들은 로그인 상태를 공유해요. 고정된 탭을 공유할지는 선택한 고정 탭 범위에 따라 달라져요. 쿠키와 로그인된 계정까지 포함해 두 스페이스를 완전히 분리하려면 서로 다른 프로필을 지정해 주세요.
:::

::: details 스페이스는 어떻게 만드나요?
사이드바의 스페이스 표시줄에서 스페이스를 만들 수 있어요. 이름을 정하고 어떤 프로필에 속할지 선택하세요. 완전히 분리된 스페이스가 필요하면 그 자리에서 **새 프로필**을 만들면 돼요.
:::

::: details 스페이스를 전환하면 어떻게 되나요?
사이드바의 탭, 북마크, 테마가 해당 스페이스에 맞게 바뀌고, Phi가 그 스페이스의 윈도우를 앞으로 가져와요(필요하면 새로 열어요). 고정된 탭은 **설정 → 스페이스**에서 선택한 스페이스, 프로필, 앱 범위에 따라 바뀌거나 그대로 유지돼요.
:::

::: details 스페이스마다 북마크와 테마가 따로 있나요?
네. 모든 스페이스는 독립된 북마크 모음을 가지며, 자기만의 색상 테마를 쓰거나 **전역 테마 따르기**를 선택할 수 있어요. 스페이스 메뉴에서 이름을 바꾸고 아이콘을 변경할 수도 있어요.
:::

::: details URL 규칙이란 무엇인가요?
URL 규칙은 링크를 어디서 클릭하거나 입력하든, 일치하는 사이트를 지정한 스페이스에서 열어 줘요. 도메인 접미사, 정확한 도메인, "도메인 포함", 호스트와 경로 접두사 조합으로 일치 조건을 정할 수 있어요. 규칙을 **매번 묻기**로 설정하면 조용히 이동시키는 대신 **어느 스페이스에서 열까요?** 프롬프트가 표시돼요. 여러 규칙이 일치할 때는 가장 구체적인 규칙이 우선해요.
:::

::: details 스페이스를 삭제하면 어떻게 되나요?
스페이스를 삭제하면 그 스페이스에 속한 북마크와 URL 규칙도 함께 삭제돼요. 이 작업은 되돌릴 수 없어요. 해당 스페이스의 스페이스 범위 고정 탭도 함께 제거되지만, 프로필 범위와 앱 범위의 고정 탭은 남아요. 스페이스를 제거해도 쿠키, 방문 기록, 로그인 정보를 담은 프로필은 삭제되지 않아요.
:::

::: details Arc나 Dia와는 어떻게 다른가요?
Phi는 **스페이스**를 눈에 보이는 작업 공간 계층으로, **프로필**을 그 아래의 격리 계층으로 유지해요. 이는 Arc의 2계층 모델과 비슷하고, Dia는 프로필을 별도 윈도우의 작업 공간으로 더 직접 사용해요. 전체 비교는 [Phi로 전환하기](/ko/switching-to-phi/)를 참고하세요.
:::

## 시크릿 스페이스

::: details 시크릿 스페이스란 무엇인가요?
사이드바 안의 프라이빗 스페이스예요. 다른 스페이스처럼 스페이스 표시줄에 나타나지만, 메모리 내 세션으로 동작해서 관련 내용이 디스크에 전혀 기록되지 않아요. **파일 → 새 시크릿 스페이스**로 열 수 있어요. 하나만 열려 있을 때는 **시크릿 모드**라는 이름이 붙고, 동시에 여러 개를 열면 **시크릿 모드 1**, **시크릿 모드 2**처럼 번호가 붙어요. 전체 그림은 가이드의 [시크릿 스페이스](/ko/incognito/)를 참고하세요.
:::

::: details 시크릿 스페이스끼리 세션을 공유하나요?
네. 열려 있는 모든 시크릿 스페이스는 하나의 프라이빗 세션을 공유해요. 한 스페이스에서 사이트에 로그인하면 다른 시크릿 스페이스에서도 로그인 상태가 돼요. 이 세션은 일반 프로필과 분리되어 있고, 기존 방식의 **새 시크릿 윈도우**와도 분리되어 있어요. 새 시크릿 윈도우의 세션은 이 세션과 절대 섞이지 않아요.
:::

::: details 시크릿 스페이스에서는 무엇을 사용할 수 없나요?
북마크와 고정된 탭은 표시되지 않고 만들 수도 없어요. 어시스턴트 채팅과 메모리 버튼을 사용할 수 없고, 브라우저 데이터 가져오기가 차단되며, 시크릿 모드에서 실행하도록 허용한 확장 프로그램만 작동해요. 테마는 Phi의 어두운 시크릿 모드 모습으로 고정돼요. 아이콘은 바꿀 수 있지만, 그 선택은 스페이스와 함께 사라져요.
:::

::: details 시크릿 스페이스를 닫으면 어떻게 되나요?
Phi가 먼저 **"이 시크릿 스페이스도 함께 닫혀요. 계속할까요?"** 대화 상자로 확인해요(**다시 묻지 않음**에 체크하면 다음부터 건너뛰어요). 그런 다음 스페이스의 윈도우를 닫고 표시줄에서 제거해요. 마지막 시크릿 스페이스 윈도우가 닫히거나 Phi가 종료되면 공유 프라이빗 세션이 삭제돼요. 다운로드한 파일은 Mac에 그대로 남아요.
:::

::: details URL 규칙이 사이트를 시크릿 스페이스로 보낼 수 있나요?
네. URL 규칙 편집기에는 일반 스페이스와 함께 범용 **시크릿 모드** 대상이 하나 제공돼요. 시크릿 스페이스는 열려 있는 동안에만 존재하므로, 규칙이 특정 시크릿 스페이스를 가리키지는 않아요. 이런 규칙이 일치하면 Phi는 열려 있는 시크릿 스페이스를 사용하거나 필요할 때 새로 열어요. 라우팅은 한 방향으로만 작동해요. 규칙이 프라이빗 세션 안의 탐색을 일반 스페이스로 다시 끌어오는 일은 없어요.
:::

::: details 확장 프로그램이 시크릿 스페이스에서 작동하나요?
개별적으로 허용하지 않는 한 작동하지 않아요. 다른 Chromium 기반 브라우저와 같아요. 프라이빗 세션은 항상 기본 프로필 위에 만들어지므로, 그 프로필의 확장 프로그램만 실행될 수 있어요. 기본 프로필의 윈도우에서 확장 프로그램 메뉴의 **확장 프로그램 관리**를 선택하고(또는 `phi://extensions` 입력), 확장 프로그램의 **세부정보**를 연 다음 **시크릿 모드에서 허용**을 켜 주세요. 다른 프로필에 설치된 확장 프로그램은 시크릿 스페이스에 나타나지 않고, 프라이빗 세션 안에서 새 확장 프로그램을 설치할 수도 없어요.
:::

::: details 시크릿 스페이스도 Time Machine 백업에 포함되나요?
아니요. 스냅샷은 시크릿 스페이스를 완전히 제외해요. 시크릿 스페이스의 세션은 윈도우와 함께 사라지도록 만들어졌기 때문이에요. 그래서 백업을 복원해도 시크릿 스페이스가 되살아나는 일은 없어요.
:::

## 북마크와 탭

::: details Phi의 북마크는 왜 다르게 느껴지나요?
Phi는 북마크를 일 년에 두 번 열어 보는 숨겨진 보관함이 아니라, 활발히 사용하는 브라우징 작업 공간의 일부로 다뤄요. 저장한 페이지는 메뉴 깊숙이 묻히지 않고 사이드바에서 계속 보이고 바로 접근할 수 있어요.
:::

::: details 여유 모드에서 북마크는 어떻게 쓰나요?
여유 모드는 Chrome과 매우 비슷하게 동작해요. **보기 → 북마크 바 항상 표시**로 북마크 바를 표시할 수 있어요. 메뉴 막대에는 **북마크** 메뉴도 있는데, 이 메뉴는 모든 레이아웃 모드에서 사용할 수 있어요.
:::

::: details 균형 모드와 성능 모드에서 북마크는 어떻게 쓰나요?
이 두 모드에는 전통적인 북마크 바가 없어요. 대신 탭을 사이드바로 드래그해서 북마크로 저장해요. 사이드바가 페이지를 정리하는 중심 공간이 돼요.
:::

::: details 탭과 북마크가 왜 같은 사이드바에 있나요?
둘은 같은 것, 즉 내가 아끼는 페이지의 양 끝이에요. 탭은 지금 사용하고 있는 페이지고, 북마크는 저장해 둔 페이지예요. 둘을 한곳에 두면 두 상태 사이를 끊임없이 오가는 사용 방식이 자연스럽게 반영돼요.
:::

::: details 고정된 탭과 북마크는 무엇이 다른가요?
고정된 탭은 사이드바 맨 위에 자리 잡고, 자주 쓰는 도구나 대시보드처럼 늘 머무는 페이지에 어울려요. 북마크는 그 아래에 있으며, 계속 활성 상태로 두지 않고 나중을 위해 보관하는 페이지예요.
:::

::: details 북마크를 클릭하면 어떻게 되나요?
그 자리에서 열려요. 일회용 탭이 새로 생기는 대신, 사이드바의 북마크 항목 자체가 살아 있는 탭이 돼요. 이미 열려 있는 북마크를 클릭하면 두 번째 사본을 만들지 않고 해당 탭을 활성화하기만 해요. 페이지를 닫아도 북마크는 사이드바에 남아 언제든 다시 열 수 있어요.
:::

::: details 북마크와 고정된 탭은 스페이스별인가요?
북마크는 항상 스페이스별이고, 스페이스마다 자기만의 북마크 모음을 유지해요. 고정된 탭은 한 스페이스에만 두거나, 같은 프로필을 쓰는 스페이스끼리 공유하거나, 앱 전체에서 공유할 수 있어요. 범위는 **설정 → 스페이스**에서 선택하고, 기본값은 **프로필**이에요. [북마크와 고정된 탭](/ko/bookmarks/#choose-a-pinned-tab-scope)을 참고하세요.
:::

::: details 탭을 고정하거나 고정 해제하려면 어떻게 하나요?
탭을 마우스 오른쪽 버튼으로 클릭하고 **고정**을 선택하거나, 사이드바 맨 위의 고정 그리드로 드래그하세요. **고정 해제**를 선택하면 탭 목록으로 돌아가요. 고정된 탭은 드래그로 순서를 바꿀 수 있고, **분할 고정**을 사용하면 두 페이지 구성을 하나의 고정 항목으로 유지할 수 있어요.
:::

::: details 고정된 탭이나 북마크를 원래 페이지로 되돌리려면 어떻게 하나요?
고정된 탭을 더블 클릭하거나, 탭으로 열려 있는 북마크의 사이트 아이콘을 클릭하세요. 현재 페이지를 유지하고 싶다면 **Command(⌘)** 키를 누른 채 고정된 탭을 더블 클릭하거나 북마크의 사이트 아이콘을 클릭하세요. 현재 페이지는 별도의 탭으로 탭 목록에 옮겨지고, 고정된 탭이나 북마크는 원래 URL로 돌아가요.
:::

::: details Arc나 Dia와 비슷한가요?
네. Phi도 저장한 페이지가 계속 보이고 고정한 페이지가 맨 위에 자리하는, 살아 있는 사이드바라는 큰 방향을 같이해요. 다만 북마크 트리와 동작 방식은 Phi만의 것을 유지해요. 이전 비교는 [Phi로 전환하기](/ko/switching-to-phi/), 기능 상세는 [북마크와 고정된 탭](/ko/bookmarks/)을 참고하세요.
:::

## Split View와 탭 그룹

::: details 탭, Split View, 탭 그룹은 어떻게 이해하면 되나요?
탭은 지금 열려 있는 페이지예요. Split View는 두 페이지를 나란히 배치해요. 탭 그룹은 관련 페이지를 프로젝트나 주제별로 모아요.
:::

::: details Split View란 무엇인가요?
Split View는 같은 Phi 윈도우 안에 두 페이지를 나란히 놓아 줘요. 읽으면서 쓰거나, 두 페이지를 비교하거나, 웹 앱 옆에 문서를 두고 볼 때 유용해요.
:::

::: details Split View는 어떻게 만드나요?
탭, 북마크, 고정된 탭을 마우스 오른쪽 버튼으로 클릭하고 **분할로 열기**를 선택하거나, 탭을 현재 페이지 위로 드래그하세요. **Option(⌥)** 키를 누른 채 고정된 탭, 북마크, 웹페이지의 링크를 클릭해도 돼요. Phi가 현재 탭 옆에 Split View로 열어 줘요.
:::

::: details 탭 그룹이란 무엇인가요?
탭 그룹은 관련 탭을 이름 있는 그룹 하나로 모아 줘요. 프로젝트, 여행, 리서치 주제, 쇼핑처럼 이어지는 작업에 편리해요.
:::

::: details Split View와 탭 그룹은 어떻게 함께 쓰나요?
둘은 함께 쓰도록 설계됐어요. 그룹 안에서 Split View를 사용할 수 있고, 분할된 탭을 그룹 안팎으로 옮길 수도 있어요. 관련 작업이 낱개 탭으로 흩어지지 않고 정돈된 상태를 유지해요.
:::

::: details 어시스턴트가 Split View나 탭 그룹 전체를 이해할 수 있나요?
네. Split View에서 대화를 시작하면 Phi가 두 페이지의 컨텍스트를 모두 사용할 수 있어요. 탭 그룹에서 시작하면 그룹 전체의 컨텍스트를 사용할 수 있어서, 상황을 설명하지 않아도 관련 페이지 전반에 대해 물어볼 수 있어요.
:::

::: details 탭 그룹은 북마크와 같은 건가요?
아니요. 탭 그룹은 지금 작업 중인 페이지를 정리하고, 북마크는 나중에 쓸 페이지를 저장해요.
:::

## AI 기능 {#ai-features}

::: details AI는 기본으로 켜져 있나요?
네. Phi는 AI 기능이 기본으로 켜진 상태로 제공돼요. AI가 제품의 핵심이기 때문이에요. 순수한 브라우저를 원한다면 끌 수 있어요.
:::

::: details AI 기능을 전부 끌 수 있나요?
네, **설정 → Phi AI**에서 끌 수 있어요. AI를 끄면 AI 대화가 종료되고, 연결된 외부 데이터 커넥터의 연결이 해제돼요. 메모리는 기기에 그대로 남아요. 메모리까지 지우려면 메모리 페이지의 지우기 옵션을 사용하세요. 이 삭제는 영구적이에요.
:::

::: details 주요 AI 구성 요소는 무엇인가요?
각자 뚜렷한 역할을 맡은 네 부분이에요. **메모리**, **어시스턴트**, **에이전트형** 기능, 그리고 **브라우저 스킬**이에요.
:::

::: details Phi 메모리란 무엇인가요?
Phi 메모리는 시간이 지나면서 내 브라우징 행동으로부터 컨텍스트를 쌓아 가는 시스템이에요. 수동 설정 없이 자동으로 동작해요.
:::

::: details 메모리를 수동으로 저장해야 하나요?
아니요. 메모리는 자동이에요. Phi가 관련 있는 브라우징 행동을 관찰해서 백그라운드에서 컨텍스트를 만들어 줘요.
:::

::: details Phi 메모리는 어디에 저장되나요?
내 기기에 로컬로 저장돼요. 로컬 우선 저장은 Phi의 핵심 설계 원칙이에요.
:::

::: details Phi가 기억하는 내용을 보거나 관리할 수 있나요?
네. 메모리 데이터는 Phi 안에서 직접 보고, 관리하고, 삭제할 수 있어요.
:::

::: details Phi가 내 메모리를 서버로 보내나요?
아니요. 메모리 데이터는 로컬에 남아요. 언어 모델이 작업을 처리할 수는 있지만, 개인 메모리가 저장이나 학습을 위해 외부로 전송되지는 않아요.
:::

::: details Phi가 내 데이터로 AI 모델을 학습시키나요?
아니요. Phi는 메모리 데이터, 브라우징 컨텍스트, AI 상호작용을 모델 학습에 사용하지 않아요.
:::

::: details 어시스턴트란 무엇인가요?
브라우저 안에서 직접 소통하는 동반자예요. 온보딩에서 이름을 지어 주면 그에 어울리는 아바타를 스스로 만들고, 그 뒤로는 그 이름으로 부르게 돼요. 그래서 평범한 챗봇 같은 느낌 대신 자기만의 정체성을 가져요.
:::

::: details 어시스턴트와는 어떻게 대화하나요?
**채팅** 버튼을 클릭하세요. 성능 모드에서는 사이드바 아래쪽에, 균형 모드와 여유 모드에서는 페이지 헤더 오른쪽 위에 있어요. 또는 페이지에서 텍스트를 선택하고 마우스 오른쪽 버튼으로 클릭한 뒤 **[어시스턴트 이름]에게 …에 대해 묻기**를 선택하면, 선택한 내용에 대해 맥락 안에서 바로 물어볼 수 있어요.
:::

::: details 어시스턴트는 무엇을 할 수 있나요?
현재 탭, Phi 메모리, 연결된 외부 데이터의 컨텍스트를 활용해 질문에 답하고, 내용을 요약하고, 페이지를 설명하고, 작업을 도와줘요.
:::

::: details "에이전트형"이라는 건 무슨 뜻인가요?
AI가 질문에 답하는 데서 그치지 않는다는 뜻이에요. 브라우저 안에서 직접 행동하고, 일회성 작업부터 반복 자동화까지 나를 대신해 작업을 수행할 수 있어요.
:::

::: details 온디맨드 작업이란 무엇인가요?
내가 요청할 때 어시스턴트가 수행하는 작업이에요. 예를 들어 나를 대신해 페이지를 이동하거나 웹사이트와 상호작용해요.
:::

::: details 예약 작업이란 무엇인가요?
내가 정한 일정에 따라 반복 실행되는 자동화예요. 예를 들어 상품 가격을 지켜보거나 페이지의 변경 사항을 감시할 수 있어요.
:::

## Phi Sentinel {#phi-sentinel}

::: details Phi Sentinel이란 무엇인가요?
Phi Sentinel은 Phi Browser의 백그라운드 AI 오케스트레이터예요. macOS 메뉴 막대에서 실행되면서 예약 작업을 수행하고 AI 작업 기록을 보관해요.
:::

::: details Phi Sentinel은 왜 브라우저와 분리되어 있나요?
브라우저 윈도우가 닫혀 있어도 예약 작업과 지속적인 AI 워크플로가 계속 실행될 수 있게 하기 위해서예요.
:::

::: details 왜 이런 설계를 택했나요?
브라우저는 가볍게 유지하면서 지속적인 자동화 계층을 따로 두면, 시스템 전체가 더 실용적이 되기 때문이에요.
:::

## Phi Link

::: details Phi Link란 무엇인가요?
Phi Link는 Phi Browser를 Telegram과 연결해 줘요. 휴대폰에서 어시스턴트를 사용하고, Mac에서 떨어져 있을 때 작업 업데이트를 받을 수 있어요.
:::

::: details Phi Link는 어떻게 설정하나요?
두 가지 방법이 있어요. 공식 Phi Link 봇을 사용하는 방법이 가장 간단해요. QR 코드를 스캔하고 클릭 한 번이면 끝나요. 아니면 BotFather로 자기만의 Telegram 봇을 만들고, 그 토큰을 Phi 설정에 붙여넣으면 돼요.
:::

::: details Phi Link로 무엇을 할 수 있나요?
어시스턴트와 대화하고, 작업이 성공하거나 실패할 때 알림을 받고, 브라우저에서 벗어나 있어도 워크플로를 이어 갈 수 있어요.
:::

::: details Phi Link도 같은 어시스턴트 정체성을 쓰나요?
네. 같은 어시스턴트 정체성이 그대로 이어져서 데스크톱과 휴대폰에서 일관된 경험을 제공해요. 자기 봇을 사용하는 경우에는 원하는 대로 맞춤 설정할 수도 있어요.
:::

## 가격과 제공 현황

::: details Phi는 무료인가요?
네, 지금은 무료예요. Phi Browser는 현재 무료로 사용할 수 있고, AI 사용량도 포함되어 있어요.
:::

::: details Phi는 영원히 무료인가요?
지금과 완전히 같은 형태로는 아닐 가능성이 커요. 앞으로 고급 기능에는 요금이 도입될 수 있어요.
:::

## 개인정보와 데이터

::: details Phi의 개인정보 보호 모델은 무엇인가요?
Phi Browser는 로컬 우선 아키텍처를 중심으로 만들어졌어요. Phi가 기억하는 내용은 내 기기에 머무르고, 학습에 사용되지 않아요.
:::

::: details Phi가 절대 수집하지 않는 것은 무엇인가요?
Phi는 메모리 데이터, AI 상호작용, 브라우징 컨텍스트를 절대 수집하지 않고, 이를 학습에 사용하지도 않아요.

다만 Phi는 항상 켜져 있는 소량의 익명 카운트(Phi를 기본 브라우저로 설정한 설치 수, 스페이스 사용 여부, 프로필 사용 여부, 충돌 발생 여부)를 보내요. 그리고 직접 켠 경우에만 상세한 사용 통계와 충돌 보고서를 보내요. [Phi가 보내는 정보](/ko/privacy/#what-phi-does-send)를 참고하세요.
:::

::: details 내 메모리는 로컬에 저장되나요?
네. 메모리 데이터는 내 기기에 있고, 직접 보고, 관리하고, 삭제할 수 있어요.
:::

::: details Phi가 내 방문 기록을 판매하거나 학습에 사용하나요?
아니요. Phi는 브라우징에서 얻은 메모리나 AI 상호작용을 모델 학습에 사용하지 않고, 브라우징에서 얻은 데이터를 판매하지도 않아요.
:::

::: details Phi가 사용 통계를 수집하나요?
네. **Phi의 기능과 성능 개선에 참여** 스위치가 켜져 있는 동안에만 Phinomenon에 익명 사용 통계를 보내고, 이 스위치는 켜진 상태로 제공돼요. 통계는 브라우저 자체에 관한 것으로, 어떤 기능이 쓰이는지와 앱 성능이 어떤지를 다뤄요. 방문한 페이지, 메모리, AI 대화는 절대 포함되지 않아요. 보고서에는 Phi 계정과 무관한 무작위 설치 식별자가 붙어요. [개인정보와 내 데이터](/ko/privacy/#usage-statistics)를 참고하세요.
:::

::: details 사용 통계는 어떻게 끄나요?
`phi://settings`를 열고 **나와 Phi** 섹션에서 **Phi의 기능과 성능 개선에 참여**를 끈 다음, 나타나는 **다시 시작** 버튼을 클릭해야 변경 사항이 적용돼요. 스위치를 끄면 이전 보고서에 붙어 있던 무작위 식별자도 삭제돼요. 나중에 다시 켜면 Phi가 새 식별자를 만들어요.
:::

## Time Machine 백업

::: details Phi의 Time Machine이란 무엇인가요?
**버전 롤백**을 위한 안전망이에요. 특정 주요 업데이트 전에 Phi가 현재 버전과 데이터의 스냅샷을 자동으로 저장해서, 새 릴리스가 잘 맞지 않으면 이전 상태로 되돌아갈 수 있어요. 전체 그림은 가이드의 [Time Machine 백업](/ko/time-machine/)을 참고하세요.
:::

::: details Apple의 Time Machine인가요?
아니요. Mac을 백업하지 않고, 같은 이름의 macOS 기능과도 관련이 없어요. Phi를 이전 버전으로 되돌리는 일만 해요.
:::

::: details 브라우징을 항상 백업하나요?
아니요. 지속 백업도, 정기 백업도 아니에요. 스냅샷은 평소보다 위험 부담이 큰 업데이트 직전에만 가끔 자동으로 만들어지고, 그런 업데이트마다 한 번만 생성돼요. 직접 관리하는 백업을 원한다면 **사용자 데이터 내보내기**를 사용하세요.
:::

::: details 스냅샷에는 무엇이 포함되나요?
이전 버전에 속한 Phi 데이터, 즉 북마크, 스페이스, 고정된 탭, 설정, 메모리, 브라우징 상태와 함께, 어떤 앱 버전으로 복원할지에 대한 기록이 포함돼요. 앱 자체는 복원 과정에서 다운로드되므로, 롤백하면 일관된 구성으로 돌아가요.
:::

::: details 스냅샷은 어디에 저장되나요?
내 Mac에 로컬로 저장돼요. 클라우드에 업로드되지 않고, 계정에 연결되지 않으며, 다른 Mac으로 옮길 수 없어요.
:::

::: details 롤백은 어떻게 하나요?
**도움말** 메뉴를 열고 **Time Machine 백업**을 선택한 다음, 버전, 빌드, 날짜로 표시된 스냅샷(예: _Phi 1.6 (590), 2026.6.11_)을 고르세요. **복원**을 확인하면 Phi가 이전 버전을 다운로드하고, 현재 앱과 그에 맞는 데이터를 교체한 뒤 다시 실행돼요. 복원하는 동안에는 인터넷 연결이 필요해요. 스냅샷이 없으면 메뉴에 **사용 가능한 백업 없음**이 표시돼요.
:::

::: details 데이터 내보내기와는 어떻게 다른가요?
Time Machine은 업데이트 롤백을 자동으로 처리해요. 새 Mac으로 옮기거나 개인 사본을 보관하기 위해 직접 백업을 만들고 관리하려면, **도움말** 메뉴의 **사용자 데이터 관리**(**사용자 데이터 내보내기…** 및 **사용자 데이터 가져오기…**)를 사용하세요.
:::

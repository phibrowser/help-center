# 從 Arc 或 Zen 移轉

**從其他瀏覽器移轉…** 會在 Phi 中重建你在 Arc 或 Zen 的整體架構。它會為每個來源設定檔建立一個 Phi 設定檔，為每個來源空間建立一個 Phi 空間，再把書籤放進各個空間，把釘選分頁和瀏覽資料放進各個設定檔。完成後，你原本的側邊欄就會在 Phi 中重現。

移轉只會新增。它永遠不會變更、合併或刪除你在 Phi 中已有的任何設定檔或空間。

## 移轉還是匯入 {#migrate-or-import}

Phi 有兩個用來帶入資料的指令，並排在 **Phi** 選單（Apple 選單旁那個粗體的 App 選單）中：

|                       | **從其他瀏覽器匯入…**           | **從其他瀏覽器移轉…**            |
| --------------------- | ------------------------------- | -------------------------------- |
| 用途                  | 把資料加入你目前所在的空間      | 建立與來源相對應的新設定檔和空間 |
| 瀏覽器                | Chrome、Safari、Arc、Dia 或檔案 | Arc 和 Zen                       |
| 資料存放位置          | 你目前的空間及其設定檔          | 它建立的新設定檔和空間           |
| 你可以選擇            | 要帶入哪些資料類型              | 要重新建立哪些空間               |
| 你在 Phi 中既有的資料 | 書籤和歷史記錄會併入既有內容    | 保持不變                         |

如果你已經有滿意的 Phi 設定，只想在其中加入書籤或歷史記錄，請選擇 **匯入**。如果你正從 Arc 或 Zen 搬過來，想讓空間恢復原本的樣子、不必手動重建，請選擇 **移轉**。匯入的說明請見 [匯入與匯出](/zh-Hant/import-export/)。

## 開始之前 {#before-you-start}

- **這台 Mac 上必須裝有該瀏覽器。** 移轉會從 Arc 或 Zen 存放資料的位置讀取資料。如果兩者都沒有安裝，**從其他瀏覽器移轉…** 會呈灰色無法點選。
- **登入 Phi，或以訪客身分繼續。** 移轉建立的設定檔和空間屬於你的 Phi 帳號，所以精靈會要求你先完成首次啟動流程，才會開始。
- **先結束 Zen。** Phi 讀取的是 Zen 檔案的副本，Zen 尚未寫入磁碟的內容都會漏掉。Zen 正在執行時，精靈會提醒你。
- **從 Arc 移轉時，預期會出現鑰匙圈提示。** Arc 會加密它的 Cookie，因此 macOS 會詢問是否允許 Phi 使用 Arc 的加密金鑰。請選擇 **永遠允許**，否則 macOS 會對每個設定檔再問一次。如果你拒絕，該設定檔的 Cookie 會留在原處，其他內容照樣移轉過來，而且報告不會標示少了這些 Cookie。
- **不要同時執行匯入。** 移轉進行期間，**從其他瀏覽器匯入…** 會呈灰色無法點選，反之亦然。

## 執行移轉 {#running-a-migration}

1. 開啟 **Phi** 選單並選擇 **從其他瀏覽器移轉…**，**移轉到 Phi** 視窗隨即開啟。
2. 選擇 **Arc** 或 **Zen**，然後按一下 **繼續**。清單只會列出這台 Mac 上已安裝的瀏覽器。
3. 在 **檢視將建立的內容** 下方檢查預覽。這裡會列出每個來源設定檔及其空間，並附上一行摘要，例如 _將建立 2 個設定檔和 5 個空間。_ 取消勾選你不需要的空間。只有在某個設定檔至少有一個空間被勾選時，才會建立該設定檔。
4. 按一下 **開始移轉**。Phi 會逐一建立設定檔和空間，並顯示進度。這可能需要幾分鐘。這段期間你可以繼續瀏覽；新空間不會蓋過你正在使用的空間。
5. 在 **移轉完成** 下方閱讀報告。按一下 **前往** 加上空間名稱的按鈕，即可切換到第一個新空間；或按一下 **完成** 關閉視窗。

## 會帶過來的內容 {#what-comes-across}

兩個瀏覽器的對應方式相同。每個來源設定檔都會變成一個 Phi 設定檔，每個來源空間都會變成一個綁定到該設定檔的 Phi 空間，並保留原本的名稱；如果 Phi 有對應的顏色和圖示，也會一併保留。

| 來源項目                                                          | 在 Phi 中                                                                           |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Arc 設定檔，或 Zen 容器（沒有容器的 Zen 空間會共用一個設定檔）    | 一個新的設定檔                                                                      |
| Arc 或 Zen 空間                                                   | 該設定檔中的一個新空間                                                              |
| Arc 側邊欄中釘選的項目，或每個 Zen 空間中的釘選分頁，連同其資料夾 | 該空間的書籤                                                                        |
| Arc 的 Favorites，或 Zen 的 Essentials                            | 釘選分頁，依你的 [釘選分頁範圍](/zh-Hant/bookmarks/#choose-a-pinned-tab-scope) 放置 |

每個設定檔底下的瀏覽資料則依瀏覽器而定：

| 資料         | Arc                                    | Zen |
| ------------ | -------------------------------------- | --- |
| 近期歷史記錄 | 是                                     | 是  |
| Cookie       | 是，需先允許鑰匙圈存取                 | 否  |
| 擴充功能     | 來自 Chrome 線上應用程式商店的擴充功能 | 否  |

有幾項限制值得了解：

- **開啟中的分頁不會移轉。** 只有釘選項目，以及 Favorites 或 Essentials 會帶過來。開著但沒有釘選的分頁會留在來源瀏覽器中。
- **歷史記錄只有近期的，並不完整。** 移轉只保留最近的歷史記錄項目，而不是你曾經造訪過的每一筆記錄。
- **擴充功能會在背景安裝。** 從 Arc 移轉時，報告會顯示有多少個 Chrome 線上應用程式商店的擴充功能已開始安裝。來自其他地方的擴充功能不會移轉，Zen 的 Firefox 擴充功能也無法在 Phi 中執行。
- **密碼和付款卡片不會移轉。**
- **Zen 的私密視窗空間會被略過。**
- **釘選分頁需要有空間。** Phi 只有在至少有一個空間要建立時，才會建立設定檔。沒有任何空間的來源設定檔（例如沒有任何 Zen 空間使用的 Zen 容器）會被略過，報告會說明有多少個釘選分頁因此留在原處。

你的來源瀏覽器不會被修改。Arc 和 Zen 原有的一切都會保留，所以你可以先移轉、比較看看，並繼續使用任一個瀏覽器。

## 閱讀報告 {#reading-the-report}

報告會列出每個設定檔和空間的處理結果：每個空間收到多少個書籤、加入了多少個釘選分頁，以及歷史記錄、Cookie 和擴充功能是否已移轉過來。如果有項目失敗，摘要會說明有多少個項目需要你留意，受影響的那一列會說明出了什麼問題，例如 **未能建立空間** 或 **書籤無法儲存**。這次執行的其他結果都會保留，所以單一失敗不會讓其餘部分跟著復原。

## 再次移轉 {#migrating-again}

Phi 會記得你曾經從某個瀏覽器移轉到你的帳號。如果你從同一個瀏覽器再開始一次移轉，Phi 會先警告你：再次移轉會建立第二組設定檔和空間，不會更新第一組。只有在你確實需要時，才選擇 **再次移轉**。如果想重新來過，請先刪除第一次移轉建立的空間再移轉（請見 [空間與設定檔](/zh-Hant/spaces/)），以免最後並排出現兩份副本。

Phi 不會與 Arc 或 Zen 持續同步。移轉是把來源當下的內容一次性複製過來。

# 常见问题

这里按主题汇总了 Phi Browser 常见问题的简短答案。要了解整体设计和 Phi 如此构建的原因，请阅读[指南](/zh-Hans/what-is-phi-browser/)。第一次使用 Phi Browser？请参阅[开始使用](/zh-Hans/get-started/)。

## 布局与导航

::: details Phi 有哪三种布局模式？
Phi 提供三种在屏幕空间与熟悉感之间取舍的模式。**性能**模式为页面留出最多空间，并使用垂直侧边栏放置标签页和书签。**均衡**模式保留侧边栏，同时在内容上方加入地址栏。**舒适**模式最接近传统浏览器，标签页位于顶部，地址栏始终可见。你会在首次使用时选择一种，并可以随时更改。
:::

::: details 应该从哪种布局开始？
如果你从 Chrome 或 Safari 迁移，请从**舒适**模式开始，过渡最轻松。如果你想使用现代侧边栏，同时保留可见地址栏，可以试试**均衡**。如果希望页面空间最大化，请使用**性能**。完整迁移说明请参阅[迁移到 Phi](/zh-Hans/switching-to-phi/)。
:::

::: details 为什么使用垂直侧边栏？
现代屏幕大多宽而不高。阅读、写作或研究时，垂直空间往往最先不够用，因此垂直侧边栏更符合现代显示器的形状，并为实际页面留出更多空间。
:::

## 空间与个人资料 {#spaces-profiles}

::: details 空间和个人资料有什么区别？
**空间**是侧边栏中的工作区，有自己的名称、图标、颜色和书签。**个人资料**是它下面的隔离层，每个个人资料都有自己的 Cookie、历史记录、登录状态和扩展程序。空间负责组织表层的内容和感受；个人资料决定哪些底层数据彼此隔离。完整说明请参阅指南中的[空间与个人资料](/zh-Hans/spaces/)。
:::

::: details 一个个人资料可以拥有多个空间吗？
可以。每个空间只属于一个个人资料，但一个个人资料可以支持多个空间。共享同一个人资料的空间会共享登录状态；是否共享固定标签页，则取决于你选择的固定标签页作用范围。如果要让两个空间完全隔离（包括 Cookie 和已登录账户），请为它们使用不同的个人资料。
:::

::: details 如何创建空间？
从侧边栏的空间栏创建空间。为它命名并选择所属个人资料；如果该空间需要完全隔离，也可以当场创建**新个人资料**。
:::

::: details 切换空间时会发生什么？
侧边栏中的标签页、书签和主题会切换为该空间的内容，Phi 也会显示对应窗口（如有需要会新开窗口）。固定标签页会根据**设置 → 空间**中选择的空间、个人资料或应用作用范围而变化或保持可见。
:::

::: details 每个空间都有自己的书签和主题吗？
是。每个空间都有独立书签，并可以使用自己的颜色主题或选择**跟随全局**。你也可以从空间菜单重命名空间并更改图标。
:::

::: details 什么是网址规则？
网址规则会把匹配的网站放到你指定的空间中，无论链接从哪里单击或输入。你可以按域名后缀、确切域名、“域名包含”，或主机加路径前缀进行匹配。将规则设置为**每次询问**，可以显示<strong>在哪个空间中打开？</strong>提示，而不是静默路由。有多条规则匹配时，最具体的一条优先。
:::

::: details 删除空间会发生什么？
删除空间也会删除属于它的书签和网址规则，且无法撤销。属于该空间的空间范围固定标签页也会被删除；个人资料范围和应用范围的固定标签页会保留。移除空间不会删除包含 Cookie、历史记录和登录状态的个人资料。
:::

::: details Phi 与 Arc 和 Dia 有何不同？
Phi 将**空间**作为可见工作区层，将**个人资料**作为底层隔离层。这接近 Arc 的双层模型，而 Dia 更直接地将个人资料作为单独窗口中的工作区。完整对比请参阅[迁移到 Phi](/zh-Hans/switching-to-phi/)。
:::

## 无痕空间

::: details 什么是无痕空间？
它是侧边栏中的私密空间。它会像其他空间一样出现在空间栏中，但底层使用内存会话，不会向磁盘写入任何相关内容。通过**文件 → 新建无痕空间**打开；一个时命名为**无痕**，同时打开多个时会依次命名为**无痕 1**、**无痕 2**等。完整说明请参阅指南中的[无痕空间](/zh-Hans/incognito/)。
:::

::: details 无痕空间之间会共享会话吗？
会。所有打开的无痕空间共享一个私密会话，因此在其中一个空间登录网站后，其他无痕空间也会处于登录状态。该会话与常规个人资料隔离，也与传统的**新建无痕式窗口**隔离，后者的会话不会与它混用。
:::

::: details 无痕空间中哪些功能不可用？
不显示书签和固定标签页，也不能创建书签；助理对话和记忆按钮不可用；浏览器数据导入会被阻止；只有获准在无痕模式中运行的扩展程序才会启用。主题固定为 Phi 的深色无痕外观；图标可以更改，但选择会随空间消失。
:::

::: details 关闭无痕空间时会发生什么？
Phi 会询问“这也会关闭此无痕空间，确定吗？”（勾选**不再询问**后可以跳过），然后关闭空间窗口并将其从空间栏移除。当最后一个无痕空间窗口关闭，或 Phi 退出时，共享的私密会话会被销毁。下载到 Mac 的文件仍会保留。
:::

::: details 网址规则可以把网站发送到无痕空间吗？
可以。网址规则编辑器会在常规空间旁提供一个通用的**无痕**目标。规则不会指向特定无痕空间，因为它们只在打开期间存在。规则匹配时，Phi 会使用现有无痕空间，或按需新建。路由是单向的：规则绝不会把私密会话中的导航拉回常规空间。
:::

::: details 扩展程序能在无痕空间中运行吗？
除非你逐一允许，否则不能。这与其他基于 Chromium 的浏览器相同。私密会话始终基于默认个人资料，因此只有该配置的扩展程序可以运行。请在默认个人资料的窗口中，从扩展程序菜单选择**管理扩展程序**（或输入 `phi://extensions`），打开扩展的**详细信息**，再开启**在无痕模式下启用**。其他个人资料中的扩展不会出现，也无法在私密会话内部安装新扩展。
:::

::: details 时间机器备份会包含无痕空间吗？
不会。快照会完全排除无痕空间，因为这类会话本就应该随窗口消失；恢复备份绝不会让无痕空间重新出现。
:::

## 书签与标签页

::: details 为什么 Phi 中的书签感觉不一样？
Phi 将书签视为活动浏览工作区的一部分，而不是一年只打开两次的隐藏档案。保存的页面会在侧边栏中保持可见和易于访问，而不是埋在菜单里。
:::

::: details 舒适模式中的书签如何使用？
舒适模式的行为很像 Chrome。选择**显示 → 始终显示书签栏**来显示书签栏。菜单栏中也有一个**书签**菜单，并且在所有布局模式中都可用。
:::

::: details 均衡和性能模式中的书签如何使用？
这两种模式没有传统书签栏。请将标签页拖入侧边栏以保存书签；侧边栏会成为整理页面的主要位置。
:::

::: details 为什么标签页和书签位于同一个侧边栏？
它们是同一件事的两个状态：你在意的页面。标签页是你当前使用的内容，书签是已经保存的内容。放在一起反映了你会不断在这两种状态之间转换。
:::

::: details 固定标签页和书签有什么区别？
固定标签页位于侧边栏顶部，适合你长期使用的页面，例如常用工具或仪表盘。书签位于其下方，用于保留稍后需要的页面，而无需让它们一直处于活动状态。
:::

::: details 单击书签时会发生什么？
书签会就地打开，因此侧边栏中的书签条目会成为实时标签页，而不会创建一个临时标签页。如果书签已经打开，再次单击只会激活对应标签页，不会创建第二份副本。关闭页面后，书签仍会留在侧边栏中，随时可以重新打开。
:::

::: details 书签和固定标签页都按空间划分吗？
书签始终按空间划分，每个空间保留自己的书签。固定标签页可以只属于一个空间、由使用同一个人资料的空间共享，或在整个应用中共享。请在**设置 → 空间**中选择作用范围。默认范围是**个人资料**。参阅[书签与固定标签页](/zh-Hans/bookmarks/#选择固定标签页的作用范围)。
:::

::: details 如何固定或取消固定标签页？
右键单击标签页并选择**固定**，或将它拖到侧边栏顶部的固定网格。选择**取消固定**会将其放回标签页列表。你可以拖动固定标签页来重新排序，也可以使用**固定分屏**把双栏布局保留为一个固定项目。
:::

::: details 如何让固定标签页或书签返回原始页面？
双击固定标签页，或单击已作为标签页打开的书签的网站图标。如果要保留当前页面，请在双击固定标签页或单击书签图标时按住 **Command (⌘)**。当前页面会作为独立标签页移到列表，而固定标签页或书签会返回原始网址。
:::

::: details 这与 Arc 或 Dia 类似吗？
是。Phi 采用相同的广义活侧边栏理念，让保存的页面保持可见，并把固定页面放在顶部，同时保留自己的书签树和行为。迁移对比请参阅[迁移到 Phi](/zh-Hans/switching-to-phi/)，功能详情请参阅[书签与固定标签页](/zh-Hans/bookmarks/)。
:::

## 分屏浏览与标签页组

::: details 应该如何理解标签页、分屏浏览和标签页组？
标签页是你当前打开的页面；分屏浏览会将两个页面并排显示；标签页组则按项目或主题收集相关页面。
:::

::: details 什么是分屏浏览？
分屏浏览会在同一个 Phi 窗口中并排放置两个页面，适合边读边写、比较页面，或将文档放在网页应用旁边。
:::

::: details 如何创建分屏浏览？
右键单击标签页、书签或固定标签页并选择**以分屏打开**，或将标签页拖到当前页面上。也可以按住 **Option (⌥)** 并单击固定标签页、书签或网页链接，Phi 会在分屏浏览中将它打开在当前标签页旁边。
:::

::: details 什么是标签页组？
标签页组会把相关标签页收进一个有名称的分组中，适合项目、旅行、研究主题或购物过程。
:::

::: details 分屏浏览和标签页组如何配合？
两者可以协同使用：你可以在组内使用分屏，也可以把分屏标签页移入或移出分组，让相关工作保持有序，而不是散落成独立标签页。
:::

::: details 助理能理解分屏浏览或整个标签页组吗？
能。从分屏浏览发起对话时，Phi 可以使用两个页面的上下文；从标签页组发起对话时，它可以使用整个分组的上下文，因此你无需解释设置，就能跨相关页面提问。
:::

::: details 标签页组和书签相同吗？
不同。标签页组整理你正在处理的页面；书签则保存供以后使用的页面。
:::

## AI 功能 {#ai-features}

::: details AI 默认开启吗？
是。Phi 默认启用 AI 功能，因为它们是产品的核心部分。如果你更喜欢纯浏览器，可以将其关闭。
:::

::: details 可以关闭全部 AI 功能吗？
可以，在**设置 → Phi AI**中操作。关闭 AI 会结束 AI 对话，并断开所有外部数据连接器。记忆仍会留在设备上；如果也想删除它，请使用记忆页面中的清除选项，该删除永久生效。
:::

::: details AI 主要由哪些部分组成？
共有四个各司其职的部分：**记忆**、**助理**、**智能体式能力**和**浏览器技能**。
:::

::: details 什么是 Phi 记忆？
Phi 记忆是一套根据你的浏览行为自动、持续建立上下文的系统，无需手动设置。
:::

::: details 需要手动保存记忆吗？
不需要。记忆会自动工作。Phi 在后台观察相关浏览行为并为你建立上下文。
:::

::: details Phi 记忆保存在哪里？
保存在你的本地设备上。本地优先存储是 Phi 的核心设计原则。
:::

::: details 可以查看或管理 Phi 记住的内容吗？
可以。你可以直接在 Phi 中查看、管理和删除记忆数据。
:::

::: details Phi 会把记忆发送到服务器吗？
不会。记忆数据留在本地。语言模型可能处理任务，但你的个人记忆不会被发送到外部存储或用于训练。
:::

::: details Phi 会用我的数据训练 AI 模型吗？
不会。Phi 不会使用你的记忆数据、浏览上下文或 AI 交互来训练模型。
:::

::: details 什么是助理？
它是你在浏览器中直接互动的伙伴。首次使用时，你会为它取名，它会生成相配的头像；之后你一直用这个名字称呼它，让它拥有自己的身份，而不是像一个通用聊天机器人。
:::

::: details 如何与助理对话？
单击**对话**按钮。性能模式中它位于侧边栏底部，均衡和舒适模式中位于页面标题栏右上角。你也可以选中网页文本、右键单击，然后选择**向［你的助理］询问…**，在上下文中针对所选内容提问。
:::

::: details 助理能做什么？
它可以利用当前标签页、Phi 记忆和已连接外部数据中的上下文，回答问题、总结内容、解释页面并协助处理任务。
:::

::: details “智能体式”是什么意思？
意思是 AI 不只回答问题，还可以在浏览器中采取操作并替你执行任务，包括一次性操作和重复自动化。
:::

::: details 什么是按需操作？
由助理在你提出要求时执行的任务，例如替你浏览页面或与网站交互。
:::

::: details 什么是定时任务？
按照你定义的计划重复运行的自动化，例如监控商品价格或观察页面变化。
:::

## Phi Sentinel {#phi-sentinel}

::: details 什么是 Phi Sentinel？
Phi Sentinel 是 Phi Browser 的后台 AI 协调器。它从 macOS 菜单栏运行，执行定时任务并保留 AI 任务历史。
:::

::: details 为什么 Phi Sentinel 与浏览器分开？
这样，定时任务和持久 AI 工作流程就能在浏览器窗口关闭后继续运行。
:::

::: details 为什么采用这种设计？
让浏览器保持轻量，同时保留持久自动化层，会使整个系统更实用。
:::

## Phi Link

::: details 什么是 Phi Link？
Phi Link 将 Phi Browser 与 Telegram 连接，让你可以从手机使用助理，并在离开 Mac 时接收任务更新。
:::

::: details 如何设置 Phi Link？
有两种方式：最简单的是使用官方 Phi Link 机器人，扫描二维码后一键完成；也可以通过 BotFather 创建自己的 Telegram 机器人，并把 token 粘贴到 Phi 设置中。
:::

::: details Phi Link 能做什么？
你可以与助理对话、在任务成功或失败时收到通知，并在离开浏览器后继续工作流程。
:::

::: details Phi Link 会使用同一个助理身份吗？
会。同一个助理身份会延续到手机，让桌面端和移动端体验保持一致；使用自己的机器人时还可以自定义外观。
:::

## 隐私与数据

::: details Phi 的隐私模型是什么？
Phi Browser 围绕本地优先架构构建：Phi 对你的记忆保存在设备上，不会用于训练。
:::

::: details Phi 明确不会收集什么？
Phi 永远不会收集你的记忆数据、AI 交互或浏览上下文，也不会用它们训练模型。

Phi 会发送少量始终启用的匿名计数（有多少安装将 Phi 设为默认浏览器、使用空间、使用个人资料，以及发生了崩溃）；只有在你主动开启时，才会发送详细使用统计和崩溃报告。参阅 [Phi 会发送什么](/zh-Hans/privacy/#what-phi-does-send)。
:::

::: details 我的记忆保存在本地吗？
是。记忆数据位于你的设备上，你可以查看、管理和删除。
:::

::: details Phi 会出售我的浏览历史或用它训练模型吗？
不会。Phi 不会用从浏览活动中获得的记忆或 AI 交互训练模型，也不会出售从浏览活动中获得的数据。
:::

::: details Phi 会收集使用统计吗？
会，但只有**帮助改进 Phi 的功能和性能**开关开启时，才会向 Phinomenon 发送匿名使用统计；该开关默认开启。统计只涉及浏览器本身，例如使用了哪些功能以及应用性能如何，绝不包含你访问的页面、记忆或 AI 对话。报告会携带一个与 Phi 账户无关的随机安装标识符。参阅[隐私与数据](/zh-Hans/privacy/#usage-statistics)。
:::

::: details 如何关闭使用统计？
打开 `phi://settings`，在**你与 Phi**部分关闭**帮助改进 Phi 的功能和性能**，然后单击出现的**重新启动**按钮，使更改生效。关闭开关也会删除旧报告所用的随机标识符；之后重新开启时，Phi 会创建一个新标识符。
:::

## 时间机器备份

::: details 什么是 Phi 时间机器？
它是一个**版本回退**安全网。在某些重大更新之前，Phi 会自动保存当前版本和数据的快照，让你在新版本不符合预期时返回旧版本。完整说明请参阅指南中的[时间机器备份](/zh-Hans/time-machine/)。
:::

::: details 这是 Apple 时间机器吗？
不是。它不会备份 Mac，与同名的 macOS 功能无关，只负责将 Phi 回退到旧版本。
:::

::: details 它会一直备份浏览数据吗？
不会。它不是持续或定时备份。只有在风险高于平常的更新之前，才会偶尔自动创建一次快照。如果你需要自行掌控的备份，请改用**导出用户数据**。
:::

::: details 快照包含什么？
快照包含属于旧版本的 Phi 数据，包括书签、空间、固定标签页、设置、记忆和浏览状态，并记录应恢复的应用版本。应用本身会在恢复期间下载，从而让回退得到一致的环境。
:::

::: details 快照保存在哪里？
只保存在你的本地 Mac 上，不会上传到云端，不与账户绑定，也无法移动到另一台 Mac。
:::

::: details 如何回退？
打开**帮助**菜单，选择**时间机器备份**，再选择一个按版本、构建号和日期列出的快照（例如 _Phi 1.6 (590)，2026.6.11_）。确认**恢复**后，Phi 会下载旧版本、替换当前应用和对应数据，然后重新启动。恢复期间需要互联网连接。如果没有快照，菜单会显示**没有可用备份**。
:::

::: details 它与导出数据有何不同？
时间机器自动处理更新回退。要创建并保留自己的备份，用于迁移到新 Mac 或保存个人副本，请使用**帮助**菜单中的**管理用户数据**（<strong>导出用户数据…</strong>和**导入用户数据…**）。
:::

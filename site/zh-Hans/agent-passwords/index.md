# 智能体密码管理器

智能体在 Phi 中工作时，迟早会遇到登录页面。把密码粘贴进对话显然是错误做法，因此 Phi 提供了更好的选择。**智能体密码管理器**会将智能体连接到你的密码管理器（目前支持 **Bitwarden**），让它们使用密码库中的登录信息进入网站。其设计目标是：在大多数情况下，**智能体完全看不到密码**。

此功能默认关闭，每一项请求都会单独询问你，而且任何长期授权都可以随时撤销。

## 为什么选择 Bitwarden

为 AI 智能体提供通往密码的路径是一项信任行为，因此背后的密码库不应是黑箱。Bitwarden **开源**，任何人都能审计其客户端和服务器；同时它**支持自行托管**，让你可以把密码库放在自己运行的服务器上，而不是别人的云端。这样，从基础设施上的密码库、到 Mac 上解锁、再到仅在你批准时释放凭据，你都能端到端掌控凭据所在位置。Phi 的辅助进程基于 Bitwarden 官方 SDK 构建，登录时也支持自托管服务器。

这里需要明确各方角色。**Bitwarden 是密码库服务提供商**，你与它的关系受 Bitwarden 条款和隐私政策约束。你可以选择将密码库放在 bitwarden.com、bitwarden.eu 或自行托管的服务器上；这个选择决定密码库位于哪里，以及受哪个法域约束。Phi 的职责是在你的 Mac 上解锁密码库，并在你批准具体请求时把单项凭据交给智能体。你的密码库和主密码都不会到达 Phinomenon。

## 如何让机密远离智能体

密码库不会在浏览器进程中打开。Phi 随应用提供一个**独立的辅助进程**，代表应用与 Bitwarden 通信，因此 Phi 登录和智能体请求所需的信息都由辅助进程持有，**密码绝不会进入浏览器进程**。解锁后的密码库密钥只存在于辅助进程内存中，密码库锁定时会立即清除。辅助进程只接受 Phi 本身的连接，而 Phi 会先验证辅助进程的代码签名，才会信任它处理数据。

此外，智能体默认通过自动填充使用登录信息，因此机密完全不会交给智能体。Phi 会自行填充页面字段，智能体只会得知填充已经完成。

## 开启功能

智能体密码管理器位于设置的**开发者**标签页中；开启**开发者模式**后才会显示：

1. 打开**设置 → 通用**并开启**开发者模式**。
2. 在**开发者**标签页找到**智能体密码管理器**，开启 **Bitwarden 密码管理器**。
3. 登录 Bitwarden 账户。支持美国、欧盟和自托管服务器，也支持启用双重登录验证的账户。然后用主密码解锁密码库。

启用时，Phi 还可能建议从 Chrome Web Store 安装 **Bitwarden 浏览器扩展程序**。这个扩展只是方便*你*在正常浏览时自动填写登录信息；智能体请求既不使用它，也不依赖它，因此选择**暂不安装**不会影响智能体访问。

## 每项请求都会先询问你

智能体请求凭据时，Phi 会显示批准提示，明确说明是**哪个智能体**在请求、需要**哪个网站或项目**，以及智能体给出的理由。在你回答之前不会释放任何内容；忽略提示后，请求会在 **60 秒后自动拒绝**。

提示提供真正的选择，而不只是“确定”：

- **批准**或**拒绝**请求。
- 选择批准持续时间：**仅一次**、**10 分钟**或**始终**。
- 可以选择将批准**应用到所有智能体**，而不只是当前请求方；一次性批准不提供此选项。

如果请求到来时密码库处于锁定状态，Phi 会先要求输入**主密码**解锁。主密码会直接交给辅助进程，浏览器不会存储。

## 三种暴露级别

不同请求的风险不同，提示会如实区分。每项请求属于以下三类之一，并用颜色标示机密会传播到多远：

| 类型              | 实际行为                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 🟢 **仅自动填充** | Phi 自行将保存的登录信息填入页面。智能体会触发填充，但**绝不会收到用户名或密码**。                                                   |
| 🟠 **命令使用**   | 凭据会释放给智能体，让它运行的命令使用，例如将数据库密码注入 CLI 环境。智能体工具会从输出中清理该值，但 Phi 无法阻止智能体自行保留。 |
| 🔴 **完全访问**   | 保存的项目会直接共享给智能体，可能是密码、备注、支付卡、身份信息或密钥；智能体可能把它记录在上下文中。                               |

已记住的批准只覆盖获批时的类型。仅自动填充的批准绝不会允许智能体直接读取密码。

自动填充还有额外安全网：填充会**绑定到来源域名**。如果智能体所在页面不属于该登录信息保存时对应的网站，Phi 会拒绝填充——这正是误导性页面试图窃取密码的方式。即使页面上的“显示密码”开关被单击，填入的密码也会保持遮盖。

## 智能体绝不会获得的内容

无论批准什么，有些界线都不可跨越：

- <strong>双重验证码绝不会释放。</strong>把实时 2FA 验证码交给智能体，会让两个验证因素都落在一次提示之后，因此这一步始终由你完成。智能体会交还控制权，由你亲自输入验证码。
- <strong>有歧义时不释放任何内容。</strong>如果多个密码库项目都匹配请求，Phi 会拒绝猜测你的账户，并要求智能体缩小范围。
- <strong>所有操作都会记录，但不记录值。</strong>审计日志会记录哪个智能体、哪个网站和哪种访问类型，绝不记录机密本身。

密码库不只包含登录信息，安全备注、支付卡、身份信息和 SSH 密钥也可能被请求，但只有登录信息可以自动填入页面。其他内容都必须经过上述明确批准提示。

## 查看和撤销批准

同一设置区域中的<strong>智能体凭据批准…</strong>会列出所有长期批准：对应智能体、网站、访问类型和持续时间。限时批准会自行过期；**始终**批准则会持续到你逐项撤销或选择**全部撤销**。

该页面还包含**允许访问所有密码**开关。这是一项有意设置的总授权，让任何智能体无需询问即可使用任意已保存登录信息。它以红色警告样式显示是有原因的，开启前 Phi 也会要求确认。除非完全理解取舍，否则请保持关闭。

## 密码库会话超时

你可以控制密码库保持解锁的时间。在智能体密码管理器中，可将**会话超时**设置为 **1 小时**、**4 小时**、**系统锁定时**、**浏览器重新启动时**（默认）或**永不**，并选择超时后的行为：**锁定**要求重新输入主密码，**退出登录**则会完全退出账户。

## 关闭功能

这些开关会真正停止功能，而不是只隐藏界面：

- 关闭 **Bitwarden 密码管理器**会锁定密码库并清除限时批准。账户登录状态会保存在磁盘上，以便以后重新启用；但功能关闭期间，所有智能体请求都会被拒绝，即使已有**始终**批准也不例外。
- 关闭**开发者模式**是总开关，会同时停用智能体访问和智能体密码管理器；再次开启时不会自动恢复任何功能，每项都必须手动重新开启。

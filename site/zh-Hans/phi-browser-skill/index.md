# phi-browser skill

**phi-browser skill** 将 Phi 与浏览器之外的 AI 编程智能体连接起来，包括 **Claude Code、Codex、Cursor、OpenClaw、Pi 和 Hermes**。将它安装到智能体后，智能体就能直接操控 Phi：打开页面、填写表单、截取屏幕、提取数据、测试网页应用，以及完成任何需要真实浏览器的工作。

::: tip 与浏览器技能不是同一回事
这里说的是单数形式的一个 skill，它属于你的编程智能体。<strong>[浏览器技能](/zh-Hans/skills/)</strong>正好是另一个方向：你在浏览器内部教给 Phi 自有助理的指令。phi-browser skill 是 Phi 提供给*你的智能体*的工具，让智能体把 Phi 当作自己的浏览器。
:::

它的特别之处在于智能体*在哪里*工作。它不会接管你的窗口，也不会另开一个功能残缺的浏览器，而是在自己的**智能体空间**中工作。那是一个使用真实登录状态、默认隐藏的浏览器窗口；你可以继续正常浏览，也可以实时查看它、随时接管，并在完成后把控制权交还。

## 智能体空间

Phi 围绕[空间](/zh-Hans/spaces/)构建，每个独立工作区都绑定一个拥有自己登录状态的个人资料。编程智能体开始任务时，Phi 会给它一个专用的**智能体空间**：一个默认隐藏的真实浏览器窗口，并在空间切换器中显示为带状态标记的小机器人（🤖）圆点。多个智能体会获得 R1、R2 等编号，方便区分。

单击圆点即可实时观看智能体工作。Phi 会原生呈现它的操作：光标滑向目标、单击产生波纹、输入字段闪烁，让你准确看到正在发生什么。观看期间，页面会忽略你自己的单击和按键，避免意外干扰智能体。只有明确按下**接管控制**按钮才能进入操作。

还有两个相关菜单项。**显示 → 智能体记录**会打开控制台，展示智能体的说明、操作和对话，你也可以从那里向它输入命令。**显示 → 智能体自动查看**会自动跟随当前正在操作的智能体。

智能体空间默认会自行整理。临时空间会在任务停止活动不久后自动关闭，避免已完成任务堆满空间切换器。只有在你明确要求时，智能体才会创建持久工作区。

## 你始终可以接管

同一时间只有一方能控制智能体空间，而且你的优先级始终更高。空间顶部的浮层会显示当前操控的智能体，并根据控制权归属提供相应操作：

- 智能体操控时，按下**接管控制**会立即停止它；在你交还控制权前，它之后尝试的任何操作都会被拒绝。
- 你操控时，**交还**会把控制权还给智能体，让它从中断处继续；**结束**则终止任务。

交接也会反向发生。当智能体遇到必须由你完成的步骤，例如登录、验证码、双重验证码或有实际后果的选择时，它会把控制权交还给你。Phi 随即显示“智能体需要你”提示，并提供直接跳到智能体空间的按钮。完成人工步骤后，单击**交还**，智能体便会继续。

## 有意识地复用你的登录状态

智能体空间会绑定你的一个现有个人资料，因此智能体可以使用你已经登录的网站。这正是功能目的：它能从你当前状态继续，而不是每次从空白浏览器开始。

你可以决定开放到什么程度。开发者标签页中的**智能体可以使用的个人资料**会限制智能体可在哪些配置中工作。如果全部禁止，Phi 会创建专用的“Agent”个人资料，让智能体仍能工作但不会接触主要登录状态。任务需要登录时，智能体不会要求你把密码粘贴到对话，而是通过[智能体密码管理器](/zh-Hans/agent-passwords/)请求，每次都需要你批准。

## 智能体的操作由你负责

这一部分值得读两遍，因为看着某个东西自动工作时，很容易忽略这一点。

操控 Phi 的智能体是在你的浏览器和会话中**以你的身份**行动。你指示它在我们的服务或其他人的服务上执行的操作，都由你负责，而且目标网站的条款与你亲自单击时完全一样地适用于你。

<strong>有些网站不允许智能体，并会采取措施。</strong>很多网站会将自动访问视为对其业务的威胁，因为内容本身就是它们的业务，因此会积极检测。Reddit 是广为人知的例子：被判定为自动化操作的账户可能受到限制或封禁；决定权在网站，而不在我们。让智能体访问不欢迎自动化的网站，可能导致你失去那里的账户、历史记录和保存的内容。风险由你承担，我们无法替你申诉或撤销后果。

<strong>有实际后果的操作必须由你授权。</strong>智能体可以购买商品、发送消息、提交表单，以及修改你已登录服务的设置。在允许之前，请检查它准备做什么。Phi 要求确认时，这个确认具有真实作用。

我们的[使用条款](https://phibrowser.com/terms/)完整说明了这些事项。

## 设置方法

所有功能都位于默认关闭的**开发者模式**之后，共分三步：

1. 在**设置 → 通用**中开启**开发者模式**。这会显示开发者标签页，其中包含智能体访问权限、授权和密码管理器。
2. 从**设置 → 开发者 → 安装 phi-browser skill**安装技能。<strong>将 skill 添加到…</strong>按钮会列出每个受支持的智能体以及**所有智能体**，并将 Phi 内置的技能链接到对应智能体的 skills 文件夹，使其随每次 Phi 更新保持最新。此功能需要 Node 22 或更高版本；新配置的智能体之后应重新启动。在 Pi 中，运行 `/reload` 即可。
3. 在**设置 → 开发者 → 智能体控制**中开启**允许智能体控制 Phi（CDP）**。设置立即生效，无需重新启动。

某个智能体第一次实际连接时，Phi 会识别发起连接的进程（包括代码签名），并询问：**允许一次**、**始终允许**或**拒绝**。在你批准之前，任何内容都无法接触浏览器。获批智能体会出现在同一标签页的**允许的智能体**中，并标记为“始终”或“本次会话”。移除后，它下次连接时会再次询问。

## 访问如何被限制

连接的设计确保未获批准的任何对象都无法访问：

- Phi 只监听**本机进程才能访问的私有 socket**，而不是网络端口。网络中的其他设备以及 Mac 上的其他用户都无法连接。
- 每个连接都需要**针对智能体单独同意**，并会验证发起进程的身份。
- 关闭<strong>允许智能体控制 Phi（CDP）</strong>会立即阻止新连接并断开现有连接。
- 默认情况下，智能体只能在**自己的智能体空间**中工作。访问你的真实浏览数据——空间、书签、固定标签页、网址规则和窗口布局——需要另一项默认关闭的权限：**允许智能体操作你的空间**。
- 关闭**开发者模式**是总开关，会同时停用智能体访问和[智能体密码管理器](/zh-Hans/agent-passwords/)；再次开启时，任何功能都不会自动恢复。

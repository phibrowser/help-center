# 从 Arc 或 Zen 迁移

**从其他浏览器迁移…** 会在 Phi 中重建你在 Arc 或 Zen 里的整体结构。它为每个来源个人资料创建一个 Phi 个人资料，为每个来源空间创建一个 Phi 空间，再把书签填进对应的空间，把固定标签页和浏览数据填进对应的个人资料。完成后，你原来的侧边栏就在 Phi 里重现了。

迁移只会新建。它从不更改、合并或删除你在 Phi 中已有的个人资料或空间。

## 迁移还是导入 {#migrate-or-import}

Phi 有两个用来带入数据的命令，并排放在 **Phi** 菜单（苹果菜单旁边加粗显示的 App 菜单）里：

|                       | **从其他浏览器导入...**          | **从其他浏览器迁移…**                |
| --------------------- | -------------------------------- | ------------------------------------ |
| 作用                  | 把数据添加到你当前所在的空间     | 新建与来源浏览器对应的个人资料和空间 |
| 支持的浏览器          | Chrome、Safari、Arc、Dia，或文件 | Arc 和 Zen                           |
| 数据去向              | 你当前的空间及其个人资料         | 它新建的个人资料和空间               |
| 你可以选择            | 要带入哪些数据类型               | 要重建哪些空间                       |
| 你在 Phi 中已有的数据 | 书签和历史记录并入已有内容       | 保持不动                             |

如果你已经有一套满意的 Phi 设置，只想往里添加书签或历史记录，选**导入**。如果你正从 Arc 或 Zen 搬过来，想让空间恢复原样，又不想手动重建，选**迁移**。导入的说明见 [导入与导出](/zh-Hans/import-export/)。

## 开始之前 {#before-you-start}

- **这台 Mac 上要装有该浏览器。** 迁移会从 Arc 或 Zen 存放数据的位置读取数据。如果两者都没有安装，**从其他浏览器迁移…** 呈灰色不可用。
- **登录 Phi，或以访客身份继续。** 迁移来的个人资料和空间属于你的 Phi 账号，所以向导会先让你完成首次运行，然后才开始。
- **先退出 Zen。** Phi 读取的是 Zen 文件的副本，Zen 还没写入磁盘的内容会被漏掉。Zen 正在运行时，向导会提醒你。
- **迁移 Arc 时会弹出钥匙串提示。** Arc 会加密它的 Cookie，所以 macOS 会询问是否允许 Phi 使用 Arc 的加密密钥。请选择**始终允许**，否则 macOS 会为每个个人资料再问一次。如果你拒绝，该个人资料的 Cookie 会留在原处，其余内容照常迁移，而且报告不会标出缺少的 Cookie。
- **不要同时运行导入。** 迁移进行期间，**从其他浏览器导入...** 呈灰色不可用，反过来也一样。

## 执行迁移 {#running-a-migration}

1. 打开 **Phi** 菜单，选择**从其他浏览器迁移…**，**迁移到 Phi** 窗口随即打开。
2. 选择 **Arc** 或 **Zen**，然后点按**继续**。列表里只会出现这台 Mac 上已安装的浏览器。
3. 在**确认将要创建的内容**下查看预览。它列出每个来源个人资料及其空间，并给出一句摘要，例如 _将创建 2 个个人资料、5 个空间。_ 取消勾选你不需要的空间。只有当某个个人资料下至少勾选了一个空间时，才会创建该个人资料。
4. 点按**开始迁移**。Phi 会逐个创建个人资料和空间，并显示进度。这可能需要几分钟。期间你可以继续浏览，新空间不会覆盖你正在使用的空间。
5. 在**迁移完成**下阅读报告。点按**前往**加上某个空间的名称，可以切换到第一个新空间；点按**完成**则关闭窗口。

## 会带过来什么 {#what-comes-across}

两个浏览器的结构对应方式相同。每个来源个人资料变成一个 Phi 个人资料，每个来源空间变成绑定到该个人资料的 Phi 空间，保留原名称；如果 Phi 有对应的颜色和图标，也会一并保留。

| 来源项目                                                            | 在 Phi 中                                                                               |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Arc 个人资料，或 Zen 容器（没有容器的 Zen 空间共用一个个人资料）    | 一个新的个人资料                                                                        |
| Arc 或 Zen 空间                                                     | 该个人资料下的一个新空间                                                                |
| Arc 侧边栏中固定的项目，或每个 Zen 空间中固定的标签页，连同其文件夹 | 该空间的书签                                                                            |
| Arc 的 Favorites，或 Zen 的常驻标签页（Essentials）                 | 固定标签页，按你的 [固定标签页范围](/zh-Hans/bookmarks/#choose-a-pinned-tab-scope) 放置 |

每个个人资料下的浏览数据取决于来源浏览器：

| 数据         | Arc                         | Zen |
| ------------ | --------------------------- | --- |
| 近期历史记录 | 是                          | 是  |
| Cookie       | 是，需获得钥匙串访问权      | 否  |
| 扩展程序     | Chrome 应用商店中的扩展程序 | 否  |

有几项限制需要知道：

- **打开的标签页不会迁移。** 只有固定的项目，以及 Favorites 或常驻标签页会带过来。打开着但没有固定的标签页会留在来源浏览器里。
- **历史记录是近期的，不是完整的。** 迁移只保留最近的历史记录条目，而不是你曾经访问过的每一条。
- **扩展程序在后台安装。** 对于 Arc，报告会显示有多少个 Chrome 应用商店扩展程序已开始安装。其他来源的扩展程序不会迁移，Zen 的 Firefox 扩展程序也无法在 Phi 中运行。
- **密码和银行卡不会迁移。**
- **Zen 的隐私窗口空间会被跳过。**
- **固定标签页需要有空间才能落地。** 只有当某个个人资料至少有一个要创建的空间时，Phi 才会创建它。没有空间的来源个人资料（例如没有任何 Zen 空间使用的 Zen 容器）会被跳过，报告会说明有多少个它的固定标签页没有被迁移。

来源浏览器不会被修改。Arc 和 Zen 原有的内容都还在，所以你可以先迁移、做个比较，然后继续使用任意一个浏览器。

## 阅读报告 {#reading-the-report}

报告列出每个个人资料和空间的处理结果：每个空间收到了多少书签，添加了多少固定标签页，以及历史记录、Cookie 和扩展程序是否已带过来。如果有失败项，摘要会说明有多少项需要你注意，出问题的那一行会说明原因，例如**空间未创建**或**书签未能保存**。这次运行的其余结果都会保留，一处失败不会撤销其他内容。

## 再次迁移 {#migrating-again}

Phi 会记住你曾从某个浏览器迁移到你的账号。如果你从同一个浏览器再次开始迁移，它会先提醒你：再次迁移会创建第二套个人资料和空间，而不会更新第一套。只有在你确实想要这样时，才选择**再次迁移**。如果想从头来过、又不想并排出现两套副本，请在再次迁移前删除第一次迁移创建的内容：先删除它的空间，再删除它的个人资料。删除空间不会删除它的个人资料，那个个人资料的 Cookie、历史记录和扩展程序都会原样保留。见[删除个人资料](/zh-Hans/spaces/#deleting-a-profile)。

Phi 不会与 Arc 或 Zen 持续同步。一次迁移就是把来源浏览器当时的内容复制一次。
